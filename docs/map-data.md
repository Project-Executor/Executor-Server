# map_data 구조 (v1)

스테이지의 맵 구성은 모두 `stages.map_data`(JSON 객체)에 담는다.
서버는 내용을 해석하지 않고 **객체인지, `hints`가 배열인지, 크기(UTF-8 최대 256KB)** 만 검사한다.
맵을 그리고 규칙대로 움직이는 것은 Unity 클라이언트가 한다. 이 문서는 클라이언트와 맵 제작(관리자 등록, 맵 에디터)이 함께 따르는 기준이다.

- 예시: [maps/tutorial/](maps/tutorial/) (튜토리얼 6개 스테이지)
- 생성·검증 스크립트: [maps/build_tutorial.py](maps/build_tutorial.py)

> v1은 튜토리얼에 필요한 요소만 정의한다. 추격 봇, 숨겨진 요소, 이상 개체(도감)는 본 스테이지를 설계할 때 추가한다 ([확장 예정](#확장-예정)).

## 1. 전체 형식

```json
{
  "version": 1,
  "theme": "hologram",
  "width": 9,
  "height": 5,
  "tiles": [
    "#########",
    "#.......#",
    "#.......#",
    "#.......#",
    "#########"
  ],
  "player": { "x": 1, "y": 1 },
  "objects": [
    { "id": "exit1", "type": "exit", "x": 7, "y": 3 }
  ],
  "dialogues": { },
  "guides": [ ],
  "story": { "intro": [ ], "outro": [ ] },
  "hints": [ ]
}
```

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `version` | O | 구조 버전. 지금은 `1` |
| `theme` | O | 맵 분위기. 튜토리얼은 `hologram` (아이템·요소를 홀로그램으로 표현) |
| `width`, `height` | O | 칸 수 |
| `tiles` | O | 지형. `height`개의 문자열, 각 문자열은 `width`글자 |
| `player` | O | 시작 위치 |
| `objects` | O | 장애물·열쇠·문·인물·출구 목록 |
| `dialogues` | | 인물 대화. 인물이 있으면 필수 |
| `guides` | | 안내 문구 (튜토리얼 조작 설명 등) |
| `story` | | 스테이지 앞뒤 나레이션 |
| `hints` | | 힌트 아이템으로 받는 힌트. **스테이지 상세 API에서는 빠지고 개수만 간다** |

### 좌표

- `x`는 왼쪽에서 오른쪽, `y`는 **위에서 아래**로 0부터 센다. `tiles[y][x]`가 그 칸이다.
- Unity Tilemap은 y가 위로 커지므로 그릴 때 `cellY = height - 1 - y`로 바꾼다.

### tiles

| 글자 | 의미 |
| --- | --- |
| `#` | 벽 (지나갈 수 없음) |
| `.` | 바닥 |

- 테두리는 모두 벽이어야 한다.
- 오브젝트는 `tiles`에 넣지 않고 `objects`에 따로 둔다 (맵 에디터에서 고치기 쉽고, 지형과 상태가 섞이지 않게).

## 2. objects

모든 오브젝트는 `id`(맵 안에서 고유), `type`, `x`, `y`를 가진다. 한 칸에는 오브젝트가 하나만 있다. 바닥(`.`) 위에만 둘 수 있다.

| type | 추가 필드 | 설명 |
| --- | --- | --- |
| `exit` | | 출구(문 아이콘). 들어가면 클리어. 맵마다 정확히 1개 |
| `crate` | | 밀 수 있는 장애물 |
| `breakable` | `hp` (1 이상) | 부술 수 있는 장애물. `hp`번 부딪히면 사라진다 |
| `key` | `keyId` | 열쇠. 그 칸에 들어가면 얻는다 |
| `door` | `keyId` | 잠긴 문. 같은 `keyId`의 열쇠가 있어야 열린다 |
| `npc` | `name`, `dialogueId` | 인물. `dialogues[dialogueId]`로 대화한다 |

## 3. 이동 규칙 (클라이언트 구현 기준)

- W(위), A(왼쪽), S(아래), D(오른쪽) 입력 하나가 행동 하나다. **상태가 바뀌는 행동만 1턴**을 쓴다.
- 이동하려는 칸에 따라:

| 이동하려는 칸 | 결과 | 턴 |
| --- | --- | --- |
| 바닥 | 이동 | 1 |
| 벽 | 아무 일도 없음 | 0 |
| `crate` | 상자가 한 칸 밀린다. **플레이어는 제자리.** 상자 너머가 바닥이고 비어 있을 때만 밀린다 (벽·다른 오브젝트가 있으면 아무 일도 없음) | 1 (밀리지 않으면 0) |
| `breakable` | `hp`가 1 줄고, 0이 되면 사라진다. 플레이어는 제자리 | 1 |
| `key` | 이동하고 열쇠를 얻는다 | 1 |
| `door` | 같은 `keyId` 열쇠가 있으면 열쇠 1개를 쓰고 문을 열며 그 칸으로 이동. 없으면 아무 일도 없음 | 1 (열쇠 없으면 0) |
| `npc` | 지나갈 수 없음 | 0 |
| `exit` | 이동하고 클리어 | 1 |

- **상호작용 키 E**: 이동 말고 무언가를 하는 입력은 모두 **E**로 한다. v1에서는 대화가 유일한 상호작용이다 (본 스테이지에서 장치 조작 등이 생기면 같은 키를 쓴다).
- **대화**: 인물 주변 3x3 칸(가로·세로·대각선으로 1칸 이내)에 있으면 **E**로 대화를 건다. 대화는 턴을 쓰지 않는다. 대화 중에는 이동 입력을 받지 않는다.
- 턴 제한은 실패 조건이 아니다. `parMoves` 이하로 클리어하면 별(★2)이 붙는다 (튜토리얼은 ★1만 있음).
- 클리어하면 사용한 턴 수를 `POST /stages/{id}/results`의 `moves`로 보낸다. 대화는 세지 않는다.

> 표의 "턴 0" 항목(벽·막힌 상자·열쇠 없는 문에 부딪힘)은 턴을 쓰지 않도록 정했다. 바꾸려면 이 문서와 `parMoves` 계산(검증 스크립트)을 같이 고친다.

## 4. dialogues

```json
"dialogues": {
  "researcher": {
    "start": "n1",
    "nodes": {
      "n1": { "speaker": "연구원", "text": "아, 깨어났군요. {characterName} 집행자님, 맞으시죠?", "next": "n2" },
      "n2": { "speaker": "연구원", "text": "무엇이 궁금하신가요?",
              "choices": [
                { "text": "여기서 나가려면?", "next": "n3" },
                { "text": "집행자가 뭐죠?", "next": "n4" }
              ] },
      "n3": { "speaker": "연구원", "text": "이 열쇠를 가져가세요.",
              "effects": [ { "type": "giveKey", "keyId": "lab" } ] }
    }
  }
}
```

- `start`에서 시작해 `next`를 따라간다. `choices`가 있으면 고른 선택지의 `next`로 간다. `next`와 `choices`가 모두 없으면 대화가 끝난다.
- `{characterName}`은 내 프로필의 집행자 이름(`GET /profiles/me`의 `characterName`)으로 바꿔 보여 준다.
- `effects`: 그 노드를 보여 줄 때 실행한다.

| effect type | 필드 | 설명 |
| --- | --- | --- |
| `giveKey` | `keyId` | 열쇠를 준다. 같은 인물에게서는 한 판에 한 번만 받는다 |

## 5. guides (안내 문구)

```json
"guides": [
  { "on": "start", "text": "W, A, S, D 키를 눌러 이동할 수 있습니다." },
  { "on": "near", "target": "crate1", "text": "상자는 밀 수 있습니다." },
  { "on": "pickup", "target": "key1", "text": "열쇠를 얻었습니다." }
]
```

| on | target | 보여 주는 때 |
| --- | --- | --- |
| `start` | | 스테이지 시작 (여러 개면 순서대로) |
| `near` | 오브젝트 id | 그 오브젝트와 처음으로 3x3 안에 들어왔을 때 |
| `pickup` | 열쇠 id | 그 열쇠를 얻었을 때 |

한 판에 각 안내는 한 번만 보여 준다.

## 6. story (나레이션)

```json
"story": {
  "intro": [
    { "type": "narration", "text": "당신은 과거의 코드들을 정리하던 도중 ..." },
    { "type": "inputCharacterName", "text": "집행자의 이름을 입력하십시오." }
  ],
  "outro": [
    { "type": "narration", "text": "{characterName} 집행자, 첫 발령지로 이동합니다." }
  ]
}
```

- `intro`는 플레이 전, `outro`는 클리어 후 결과 화면 전에 순서대로 보여 준다.

| type | 설명 |
| --- | --- |
| `narration` | 나레이션 문장 한 줄 |
| `inputCharacterName` | 집행자 이름 입력 창. 입력값은 `PATCH /profiles/me`의 `characterName`으로 저장한다. **이미 이름이 있으면 건너뛴다** (로그인 응답의 `hasCharacterName`) |

## 7. hints

```json
"hints": ["열쇠는 오른쪽 벽 너머에 있다.", { "text": "봇은 두 칸마다 움직인다.", "x": 2, "y": 3 }]
```

- 문자열 또는 객체. 서버는 형식을 보지 않는다.
- 스테이지 상세(`GET /stages/{id}`)에는 빠지고 `hintCount`만 간다. 내용은 `POST /stages/{id}/hint`로 받는다.
- 튜토리얼은 힌트를 쓰지 않는다 (`[]`).

## 8. 튜토리얼 스테이지

작전 `Tutorial`(sort_order 0)의 6개 스테이지. 모두 `stageType: TUTORIAL`이라 별은 ★1(클리어)만 있다.

| No | 제목 | 크기 | 가르치는 것 | 최소 턴 | 보상 |
| --- | --- | --- | --- | --- | --- |
| 1 | 시뮬레이션 1: 이동 | 9x7 | W·A·S·D 이동 (네 방향을 모두 써야 하는 꺾인 길). 시작 전에 도입 나레이션과 집행자 이름 입력 | 22 | 10 |
| 2 | 시뮬레이션 2: 장애물 | 9x6 | 상자를 옆 빈칸으로 밀어 길 열기, 블록(hp 2) 두 번 부수기 | 12 | 10 |
| 3 | 시뮬레이션 3: 열쇠 | 9x5 | 아래쪽 방에서 열쇠를 얻고 돌아와 문 열기 | 16 | 10 |
| 4 | 시뮬레이션 4: 인물 | 11x5 | 3x3 안에서 대화, 선택지, 대화로 열쇠 받기 | 8 | 10 |
| 5 | 시뮬레이션 5: 종료 | 11x9 | 막다른 길이 있는 미로에서 출구(문 아이콘) 찾기 | 20 | 10 |
| 6 | 시뮬레이션 6: 종합 | 13x8 | 상자 밀기 → 블록 부수기 → 감독관 대화로 열쇠 → 문 → 출구. 클리어 후 종료 나레이션 | 29 | 50 |

- `parMoves`는 검증 스크립트가 계산한 최소 턴이다 (튜토리얼은 별 조건으로 쓰지 않음).
- 각 스테이지는 가르치는 요소를 **반드시 거쳐야** 클리어할 수 있게 만들었다 (스크립트의 최소 풀이로 확인).
- 보상 코인은 임시 값이다 (요구사항 "보상 수치" 미정).

### 등록

`maps/tutorial/stage-N.json`은 관리자 API `POST /api/admin/stages` 본문에서 `operationId`만 빠진 형식이다.
Tutorial 작전의 `operationId`를 넣어 그대로 보내면 된다.

### 고치는 방법

1. `maps/build_tutorial.py`의 `STAGES`에서 맵 그림·대사·안내를 고친다.
2. `python docs/maps/build_tutorial.py`를 실행한다. 구조 검사와 풀이를 통과해야 JSON이 만들어지고, 최소 턴이 `parMoves`로 들어간다.
3. 등록된 스테이지는 `PUT /api/admin/stages/{id}`로 갱신한다 (기록은 유지된다).

## 확장 예정

본 스테이지를 설계할 때 추가할 것 (v2):

- 추격 봇: 플레이어를 따라오는 봇, 닿으면 게임 오버
- 숨겨진 요소: 숨겨진 버그(처치) 또는 피스(수집). 달성하면 결과 제출의 `hiddenFound: true` (★3)
- 이상 개체: 오브젝트에 `guidebookId`를 달아, 만나면 결과 제출의 `encounteredGuidebookIds`에 넣는다
- 대화 effect 추가 (문 열기, 플래그 등)
