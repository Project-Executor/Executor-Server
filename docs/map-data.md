# map_data 구조 (v1)

스테이지의 맵 구성은 모두 `stages.map_data`(JSON 객체)에 담는다.
서버는 내용을 해석하지 않고 **객체인지, `hints`가 배열인지, 크기(UTF-8 최대 256KB)** 만 검사한다.
맵을 그리고 규칙대로 움직이는 것은 Unity 클라이언트(`Assets/Scripts/Game/Board.cs`)가 한다.
이 문서는 클라이언트와 맵 제작(관리자 등록, 맵 에디터)이 함께 따르는 기준이다.

- 예시: [maps/tutorial/](maps/tutorial/) (튜토리얼 6개 스테이지)
- 생성·검증 스크립트: [maps/build_tutorial.py](maps/build_tutorial.py)

## 0. 요소 한눈에 보기

맵에 놓을 수 있는 모든 요소. **지형은 `tiles`**, 위치마다 동작·상태가 있는 것은 **`objects`** 에 둔다.

### 지형 (`tiles`)

| 글자 | 이름 | 지나갈 수 있음 | 상태 |
| --- | --- | --- | --- |
| `#` | 벽 | X | 구현됨 |
| `.` | 바닥 | O | 구현됨 |

> 지형에는 "지나갈 수 있는지"만 담는다. 밟으면 무언가 일어나는 칸(체크포인트 등)도 오브젝트로 만든다.
> 지형 글자를 늘리면 모든 맵 문자열의 의미가 바뀌므로, 새 요소는 되도록 오브젝트로 추가한다.

### 오브젝트 (`objects[].type`)

| type | 이름 | 막음 | 추가 필드 | 그림 기호 | 상태 |
| --- | --- | --- | --- | --- | --- |
| `exit` | 출구 (문 아이콘) | X (들어가면 클리어) | | `E` | 구현됨 |
| `crate` | 상자 | O (밀 수 있음) | | `C` | 구현됨 |
| `breakable` | 부서지는 블록 | O (부딪혀 부숨) | `hp` | `B` | 구현됨 |
| `key` | 열쇠 | X (들어가면 얻음) | `keyId` | `K` | 구현됨 |
| `door` | 잠긴 문 | 열쇠 없으면 O | `keyId` | `D` | 구현됨 |
| `npc` | 인물 | O | `name`, `dialogueId` | `N` | 구현됨 |
| `checkpoint` | 체크포인트 | X (들어가면 다음 구간 시작, 워프 지점) | `order`, `turns` | `S` | 구현됨 |
| `hidden` | 숨겨진 요소 (버그·피스) | X (들어가면 수집) | `name` (선택) | `H` | 구현됨 |
| `anomaly` | 이상 개체 | O | `guidebookId`, `name` | `A` | 구현됨 |
| `fakeWall` | 가짜 벽 | X (벽처럼 보이지만 지나감) | | `F` | 구현됨 |
| (예정) | 추격 봇 | | | | [확장 예정](#9-확장-예정) |

- 시작 위치는 오브젝트가 아니라 `player` 필드다 (그림 기호 `P`).
- 그림 기호는 [build_tutorial.py](maps/build_tutorial.py)에서 맵을 ASCII로 그릴 때 쓰는 글자다. JSON에는 들어가지 않는다.
- 클라이언트는 **모르는 type을 바닥처럼 지나간다** (새 요소가 든 맵을 이전 버전이 열어도 멈추지 않게).

## 1. 전체 형식

```json
{
  "version": 1,
  "theme": "hologram",
  "width": 9,
  "height": 5,
  "tiles": [
    "#########",
    "#.......#",
    "#.......#",
    "#.......#",
    "#########"
  ],
  "player": { "x": 1, "y": 1 },
  "objects": [
    { "id": "exit1", "type": "exit", "x": 7, "y": 3 }
  ],
  "dialogues": { },
  "guides": [ ],
  "story": { "intro": [ ], "outro": [ ] },
  "hints": [ ]
}
```

| 필드 | 필수 | 설명 |
| --- | --- | --- |
| `version` | O | 구조 버전. 지금은 `1` (필드·type 추가는 같은 버전에서 한다) |
| `theme` | O | 맵 분위기. 튜토리얼은 `hologram` (아이템·요소를 홀로그램으로 표현) |
| `width`, `height` | O | 칸 수 |
| `tiles` | O | 지형. `height`개의 문자열, 각 문자열은 `width`글자 |
| `player` | O | 시작 위치 |
| `objects` | O | 오브젝트 목록 ([2장](#2-objects)) |
| `dialogues` | | 인물 대화. 인물이 있으면 필수 ([4장](#4-dialogues)) |
| `guides` | | 안내 문구 ([5장](#5-guides-안내-문구)) |
| `story` | | 스테이지 앞뒤 나레이션 ([6장](#6-story-나레이션)) |
| `hints` | | 힌트 아이템으로 받는 힌트. **스테이지 상세 API에서는 빠지고 개수만 간다** ([7장](#7-hints)) |
| `stars` | | 별 조건 설정. `{ "maxUnstable": 0 }` (없으면 기본값) ([3.4](#34-별-조건)) |
| `camera` | | 화면에 보일 칸 수. `{ "width": 15, "height": 9 }` (없으면 자동) ([3.8](#38-카메라와-미니맵)) |
| `minimap` | | 미니맵 설정. `{ "revealRadius": 2 }` (없으면 기본값) ([3.8](#38-카메라와-미니맵)) |

### 좌표

- `x`는 왼쪽에서 오른쪽, `y`는 **위에서 아래**로 0부터 센다. `tiles[y][x]`가 그 칸이다.
- Unity Tilemap은 y가 위로 커지므로 그릴 때 `cellY = height - 1 - y`로 바꾼다.

### 지형 규칙

- 테두리는 모두 벽이어야 한다.
- 오브젝트는 `tiles`에 넣지 않고 `objects`에 따로 둔다 (맵 에디터에서 고치기 쉽고, 지형과 상태가 섞이지 않게).

## 2. objects

모든 오브젝트는 공통으로 `id`(맵 안에서 고유), `type`, `x`, `y`를 가진다.

- 한 칸에는 오브젝트가 하나만 있다.
- 바닥(`.`) 위에만 둘 수 있다.
- 플레이어 시작 칸에는 둘 수 없다.

| type | 추가 필드 | 설명 |
| --- | --- | --- |
| `exit` | | 출구. 들어가면 클리어. **맵마다 정확히 1개** |
| `crate` | | 밀 수 있는 장애물 |
| `breakable` | `hp` (1 이상, 없으면 1) | 부술 수 있는 장애물. `hp`번 부딪히면 사라진다 |
| `key` | `keyId` | 열쇠. 그 칸에 들어가면 얻는다 |
| `door` | `keyId` | 잠긴 문. 같은 `keyId`의 열쇠가 있어야 열린다 |
| `npc` | `name`, `dialogueId` | 인물. `dialogues[dialogueId]`로 대화한다 |
| `checkpoint` | `order` (1 이상, 맵 안에서 고유), `turns` (1 이상) | 체크포인트. 구간을 나누고 워프 지점이 된다 ([3.3](#33-체크포인트-checkpoint)) |
| `hidden` | `name` (선택, 화면에 표시할 이름) | 숨겨진 요소. 처음에는 보이지 않고 3x3 안에 들어오면 드러난다. 들어가면 수집한다 ([3.4](#34-별-조건)) |
| `anomaly` | `guidebookId` (도감 ID, 필수), `name` | 이상 개체. 칸을 막는다. 3x3 안에 처음 들어오면 만난 것으로 기록되고 도감이 해금된다 ([3.6](#36-숨겨진-요소와-이상-개체)) |
| `fakeWall` | | 가짜 벽. 벽과 똑같이 보이지만 지나갈 수 있고, 처음 들어가면 드러난다 ([3.7](#37-가짜-벽-fakewall)) |

예:

```json
"objects": [
  { "id": "exit1",  "type": "exit",      "x": 7, "y": 3 },
  { "id": "crate1", "type": "crate",     "x": 3, "y": 1 },
  { "id": "block1", "type": "breakable", "x": 5, "y": 3, "hp": 2 },
  { "id": "key1",   "type": "key",       "x": 4, "y": 3, "keyId": "lab" },
  { "id": "door1",  "type": "door",      "x": 4, "y": 1, "keyId": "lab" },
  { "id": "npc1",   "type": "npc",       "x": 3, "y": 3, "name": "연구원", "dialogueId": "researcher" },
  { "id": "cp1",    "type": "checkpoint", "x": 6, "y": 2, "order": 1, "turns": 10 },
  { "id": "hidden1", "type": "hidden",    "x": 2, "y": 3, "name": "버그 조각" },
  { "id": "npe",    "type": "anomaly",   "x": 6, "y": 1, "guidebookId": 3, "name": "NullPointerException" },
  { "id": "fake1",  "type": "fakeWall",  "x": 1, "y": 2 }
]
```

## 3. 규칙 (클라이언트 구현 기준)

### 3.1 이동

W(위), A(왼쪽), S(아래), D(오른쪽) 입력 하나가 행동 하나다. **상태가 바뀌는 행동만 1턴**을 쓴다.

| 이동하려는 칸 | 결과 | 턴 |
| --- | --- | --- |
| 바닥 | 이동 | 1 |
| 벽 | 아무 일도 없음 | 0 |
| `crate` | 상자가 한 칸 밀린다. **플레이어는 제자리.** 상자 너머가 바닥이고 비어 있을 때만 밀린다 (벽·다른 오브젝트가 있으면 아무 일도 없음. 가짜 벽도 오브젝트라 밀어 넣을 수 없다) | 1 (밀리지 않으면 0) |
| `breakable` | `hp`가 1 줄고, 0이 되면 사라진다. 플레이어는 제자리 | 1 |
| `key` | 이동하고 열쇠를 얻는다 | 1 |
| `door` | 같은 `keyId` 열쇠가 있으면 열쇠 1개를 쓰고 문을 열며 그 칸으로 이동. 없으면 아무 일도 없음 | 1 (열쇠 없으면 0) |
| `npc` | 지나갈 수 없음 | 0 |
| `checkpoint` | 이동하고 지금 구간이 끝난다. 다음 구간이 그 체크포인트의 `turns`로 시작한다 ([3.3](#33-체크포인트-checkpoint)) | 1 |
| `hidden` | 이동하고 수집한다 (보이지 않던 것도 들어가면 수집) | 1 |
| `anomaly` | 지나갈 수 없음 | 0 |
| `fakeWall` | 이동한다. 처음이면 드러난다 | 1 |
| `exit` | 이동하고 클리어 | 1 |

> "턴 0" 항목(벽·막힌 상자·열쇠 없는 문에 부딪힘)은 턴을 쓰지 않도록 정했다. 바꾸려면 이 문서와 검증 스크립트의 최소 턴 계산을 같이 고친다.

### 3.2 턴 제한

- 맵은 체크포인트로 **구간**을 나눈다. 체크포인트가 없으면 시작 위치부터 출구까지가 한 구간이다.
  - 구간 0: 시작 위치 → 다음 체크포인트(또는 출구). 쓸 수 있는 턴은 스테이지 `parMoves`
  - 구간 k (k ≥ 1): `order`가 k인 체크포인트 → 다음 체크포인트(또는 출구). 쓸 수 있는 턴은 그 체크포인트의 `turns`
- 게임의 목표는 **"기준 턴 안에 다음 체크포인트(또는 출구)까지 가기"** 다. 화면에는 **남은 턴 = 구간 기준 턴 − 구간 사용 턴**을 보여 준다 (예: 기준 15, 사용 0이면 15 → 14 → … → 0).
- 남은 턴이 0 밑으로 내려가도 실패하지 않고 계속 움직일 수 있다. 대신 다음 체크포인트(또는 출구)에 도착할 때 **불안정**으로 기록된다 ([3.3](#33-체크포인트-checkpoint)).
  - 이때 화면에는 남은 턴을 **-1, -2처럼 빨간색으로** 보여 준다 (예: 기준 15, 사용 18이면 -3). 턴 안에 못 들어왔다는 것이 바로 보이게 한다.
- 턴을 쓰지 않는 입력(위 표의 "턴 0"), 대화, 워프로는 남은 턴이 줄지 않는다.

클라이언트가 세는 값:

| 값 | 설명 |
| --- | --- |
| 구간 사용 턴 | 지금 구간에서 쓴 턴. 체크포인트에 도착하거나 워프하면 0부터 다시 센다. 남은 턴 = 구간 턴 − 구간 사용 턴 |
| 구간 최고 기록 | 구간마다, 그 구간을 **통과할 때**(다음 체크포인트·출구에 도착할 때) 쓴 턴 중 가장 적은 값 |
| 전체 사용 턴 | 워프와 관계없이 누른 턴 전체 (통계용) |

### 3.3 체크포인트 (`checkpoint`)

긴 맵을 여러 구간으로 나누고, 도착한 체크포인트끼리 워프할 수 있게 하는 칸.

| 필드 | 설명 |
| --- | --- |
| `order` | 구간 번호. 1부터, 맵 안에서 겹치지 않게. 플레이 순서대로 매긴다 |
| `turns` | 이 체크포인트에서 시작하는 구간에서 쓸 수 있는 턴 |

**도착**

- 체크포인트 칸으로 들어가는 이동은 1턴을 쓴다. 그 턴까지 센 뒤 지금 구간을 판정한다.
  - 남은 턴이 0 이상이면 **안정**, 음수면 **불안정**
- 도착하면 그 체크포인트가 **워프 지점으로 등록**되고, 다음 구간이 `turns`로 시작한다.
- 지나갈 수 있는 칸이다. 다만 칸을 차지하는 오브젝트라서 상자를 밀어 넣을 수는 없다. 한 번 도착해도 사라지지 않는다.
- **지금 구간보다 번호가 큰 체크포인트에 들어갈 때만 도착**이다. 지나온 체크포인트(번호가 같거나 작은)는 바닥처럼 지나간다. 돌아가려면 워프한다.
- 출구도 마지막 구간의 끝이라서 같은 기준으로 안정·불안정을 판정한 뒤 클리어한다.

**워프 (되돌리기)**

- 플레이 중 언제든 **도착한 적 있는 체크포인트(시작 위치 포함) 중 원하는 곳**으로 워프할 수 있다. 앞쪽으로도, 뒤쪽으로도 갈 수 있다.
- 워프하면 그 체크포인트에 **마지막으로 도착했을 때의 맵 상태**로 돌아간다.
  - 복원: 플레이어 위치, 상자 위치, 블록 hp, 가진 열쇠, 열린 문, 대화로 받은 열쇠 기록
  - 유지(복원하지 않음): **찾은 숨겨진 요소, 만난 이상 개체(도감)**, 체크포인트별 안정·불안정 기록, 구간 최고 기록, 이미 본 안내(guides)
- 워프는 턴을 쓰지 않는다. 워프한 체크포인트의 구간을 처음부터 다시 시작한다 (구간 사용 턴 0).
- 같은 체크포인트에 다시 도착하면 그때의 상태로 저장 상태를 덮어쓴다. 상자를 막힌 곳에 넣은 채 도착했더라도 더 앞의 체크포인트로 워프하면 되므로 진행 불가 상태는 남지 않는다.

**안정·불안정**

- 체크포인트(와 출구)마다 **가장 좋았던 도착**을 기록한다. 한 번이라도 안정으로 도착했으면 안정이다.
- 불안정하게 도착했어도 워프로 앞 구간에 돌아가 턴 안에 다시 오면 안정으로 바뀐다.
- 클리어할 때 불안정한 체크포인트(출구 포함) 수를 `unstableCount`로 결과 제출에 보낸다 (별 조건).

**결과 제출 (`POST /stages/{id}/results`)**

| 필드 | 값 |
| --- | --- |
| `moves` | **구간 최고 기록의 합.** 순위(최소 턴 순위)에 쓰인다. 탐색하다 워프로 돌아가 다시 깔끔하게 통과하면 그 기록만 남으므로, 둘러보는 것이 손해가 아니다 |
| `unstableCount` | 불안정한 체크포인트(출구 포함) 수 |
| `rewinds` | 워프한 횟수 (통계용, 선택) |
| `hiddenFound` | 맵의 숨겨진 요소(`hidden`)를 **모두** 모았는지 (워프해도 유지). 맵에 없으면 `false` |
| `encounteredGuidebookIds` | 만난 이상 개체의 `guidebookId` (워프해도 유지, 클리어하지 못해도 보낸다) |

> 상태: 서버 결과 제출(`unstableCount`·★2 판정), 관리자 웹 맵 편집기(체크포인트·숨겨진 요소·이상 개체 도구), 클라이언트 규칙(`Board`)은 구현됨. 검증 스크립트(`build_tutorial.py`)는 아직이다.
> 체크포인트가 없는 맵은 구간이 하나라서 지금 동작과 같다 (출구 도착 때만 안정·불안정 판정).

### 3.4 별 조건

| 별 | 조건 |
| --- | --- |
| ★1 | 클리어 |
| ★2 | 불안정한 체크포인트(출구 포함)가 `stars.maxUnstable`개 **이하** (기본 0 = 모든 구간을 턴 안에) |
| ★3 | 맵의 숨겨진 요소(`hidden`)를 **모두** 수집 (`hiddenFound`). 숨겨진 요소가 없는 맵은 ★3을 얻을 수 없다 |

- `stars.maxUnstable`은 맵마다 정한다. 구간이 많고 어려운 맵은 1~2로 여유를 줄 수 있다.
- 튜토리얼(`stageType: TUTORIAL`)은 ★1만 있다.

### 3.5 상호작용과 대화

- **상호작용 키 E**: 이동 말고 무언가를 하는 입력은 모두 **E**로 한다. 지금은 대화가 유일한 상호작용이다 (장치 조작 등이 생기면 같은 키를 쓴다).
- **대화**: 인물 주변 3x3 칸(가로·세로·대각선으로 1칸 이내)에 있으면 **E**로 대화를 건다. 3x3 안에 여럿이면 가장 가까운 인물.
- 대화는 턴을 쓰지 않는다. 대화 중에는 이동 입력을 받지 않는다.

### 3.6 숨겨진 요소와 이상 개체

**숨겨진 요소 (`hidden`)**

- 처음에는 화면·미니맵에 보이지 않는다. 플레이어 주변 3x3 안에 들어오면 **드러나고**, 그 뒤로는 계속 보인다.
- 그 칸으로 들어가면 1턴을 쓰고 수집한다. 보이지 않던 칸에 바로 들어가도 수집한다.
- 화면 오른쪽 위 "수집 n/m"에 모은 수 / 맵의 수를 보여 준다. 모두 모으면 ★3.
- 워프해도 **수집과 드러남은 유지**된다 (멀리 있는 숨겨진 요소를 모으러 워프로 돌아가도 된다).

**이상 개체 (`anomaly`)**

- 칸을 막는다 (인물처럼 지나갈 수 없음). 화면에 보인다.
- 플레이어 주변 3x3 안에 **처음** 들어오면 만난 것으로 기록하고 "도감 기록" 알림을 띄운다.
- 결과 제출의 `encounteredGuidebookIds`로 보내면 서버가 도감을 해금한다 (클리어하지 못해도). 없는 도감 ID는 서버가 무시한다.
- 워프해도 **만남 기록은 유지**된다. `near` 안내의 `target`으로도 쓸 수 있다.

### 3.7 가짜 벽 (`fakeWall`)

- 바닥(`.`) 칸에 오브젝트로 둔다. 처음에는 화면·미니맵에 **진짜 벽과 똑같이** 그린다. 3x3 안에 들어와도 드러나지 않는다.
- 그 칸으로 들어가면 1턴을 쓰고 지나간다. **처음 들어갈 때 드러나고** "가짜 벽이었습니다" 알림을 띄운다. 그 뒤로는 바닥처럼 지나간다.
- 드러난 뒤에도 **게임 화면에서는 계속 진짜 벽과 똑같이** 그린다. **미니맵에만** 어두운 회색으로 표시해 찾은 길을 알 수 있게 한다.
- 상자는 가짜 벽 칸으로 밀어 넣을 수 없다 (벽처럼 보이는 칸이므로).
- 워프해도 **드러남은 유지**된다 (위치를 알아낸 것은 되돌리지 않는다).
- 최소 턴 계산(관리자 웹)은 가짜 벽을 바닥으로 본다. 그래서 기준 턴은 가짜 벽을 아는 사람 기준이 된다. 가짜 벽을 지름길로 쓰는 맵은 기준 턴을 넉넉히 잡거나 `stars.maxUnstable`로 여유를 준다.
- `near` 안내의 `target`으로 쓰면 정체가 드러나므로, 힌트(`hints`)로 알려 주는 것을 권한다.

### 3.8 카메라와 미니맵

```json
"camera":  { "width": 15, "height": 9 },
"minimap": { "revealRadius": 2 }
```

**카메라 (`camera`)**

- 평소 화면(구간 보기)에 보일 칸 수다. 카메라는 플레이어를 따라가고, 맵 가장자리에서는 맵 바깥이 보이지 않게 멈춘다. 크기는 판 내내 같다.
- `width`·`height`는 3 이상 정수. 둘 다 적으면 둘 다 들어가는 크기로, 한쪽만 적으면 그쪽에 맞추고 다른 쪽은 화면 비율대로 보인다. 맵보다 크면 맵 크기까지만.
- 없으면 자동: 시작 → 체크포인트 → 출구 구간 중 가장 넓은 구간 + 여백 2칸 (최소 9×7, 맵 크기 이하).
- **M** 키(맵 전체 보기)는 이 값과 상관없이 맵 전체를 보여 준다.

**미니맵 (`minimap`)**

- 미니맵(과 전체 맵 팝업)은 처음에 가려져 있고, 플레이어 둘레 `revealRadius`칸 안이 지나가는 대로 밝혀진다 (기본 2 = 5×5). 1 이상 정수.
- 밝혀지지 않은 칸은 검게, 그 칸의 오브젝트는 그리지 않는다. 플레이어 위치는 항상 보인다.
- 밝힌 곳은 워프해도 유지된다. 처음부터 전체를 보여 주려면 맵 크기 이상으로 적는다.

## 4. dialogues

```json
"dialogues": {
  "researcher": {
    "start": "n1",
    "nodes": {
      "n1": { "speaker": "연구원", "text": "아, 깨어났군요. {nickname} 집행자님, 맞으시죠?", "next": "n2" },
      "n2": { "speaker": "연구원", "text": "무엇이 궁금하신가요?",
              "choices": [
                { "text": "여기서 나가려면?", "next": "n3" },
                { "text": "집행자가 뭐죠?", "next": "n4" }
              ] },
      "n3": { "speaker": "연구원", "portrait": "researcher/smile", "text": "이 열쇠를 가져가세요.",
              "effects": [ { "type": "giveKey", "keyId": "lab" } ] }
    }
  }
}
```

| 노드 필드 | 설명 |
| --- | --- |
| `speaker` | 이름표에 표시할 이름. 없으면 인물의 `name` |
| `text` | 대사. `{nickname}`은 내 닉네임(`GET /profiles/me`의 `nickname`)으로 바꿔 보여 준다 (없으면 "집행자") |
| `portrait` | 스탠딩 일러스트 `"인물ID/표정"` 또는 `"인물ID"` (선택). 없으면 `speaker`로 인물을 찾고 표정은 `default` |
| `next` | 다음 노드 id. `choices`가 없을 때 쓴다 |
| `choices` | 선택지 `[{ "text", "next" }]` |
| `effects` | 그 노드를 보여 줄 때 실행 |

- `start`에서 시작해 `next`를 따라간다. `choices`가 있으면 고른 선택지의 `next`로 간다. `next`와 `choices`가 모두 없으면 대화가 끝난다.

| effect type | 필드 | 설명 |
| --- | --- | --- |
| `giveKey` | `keyId` | 열쇠를 준다. 같은 인물에게서는 한 판에 한 번만 받는다 |

## 5. guides (안내 문구)

```json
"guides": [
  { "on": "start", "text": "W, A, S, D 키를 눌러 이동할 수 있습니다." },
  { "on": "near", "target": "crate1", "text": "상자는 밀 수 있습니다." },
  { "on": "pickup", "target": "key1", "text": "열쇠를 얻었습니다." }
]
```

| on | target | 보여 주는 때 |
| --- | --- | --- |
| `start` | | 스테이지 시작 (여러 개면 순서대로) |
| `near` | 오브젝트 id | 그 오브젝트와 처음으로 3x3 안에 들어왔을 때 |
| `pickup` | 열쇠 id | 그 열쇠를 얻었을 때 |

- 한 판에 각 안내는 한 번만 보여 준다.
- 게임 화면에서는 알림과 함께 왼쪽 퀘스트 패널에 남는다 (최근 2개).

## 6. story (나레이션)

```json
"story": {
  "intro": [
    { "type": "narration", "text": "당신은 과거의 코드들을 정리하던 도중 ..." },
    { "type": "inputNickname", "text": "집행자의 이름을 입력하십시오." }
  ],
  "outro": [
    { "type": "narration", "text": "{nickname} 집행자, 첫 발령지로 이동합니다." }
  ]
}
```

- `intro`는 플레이 전, `outro`는 클리어 후 결과 화면 전에 순서대로 보여 준다.
- 챕터 내비게이터의 "스토리"는 그 챕터 첫 스테이지의 `intro`(닉네임 입력 제외)를 다시 보여 준다.

| type | 설명 |
| --- | --- |
| `narration` | 나레이션 문장 한 줄 |
| `inputNickname` | 닉네임 입력 창 (중복 확인 버튼 포함). `GET /profiles/check-nickname`로 확인하고 `PATCH /profiles/me`의 `nickname`으로 저장한다. **이미 닉네임이 있으면 건너뛴다** (로그인 응답의 `hasNickname`) |

### 고치는 방법

3. Unity 프로젝트의 `Assets/Resources/Maps/tutorial/`에도 복사한다 (오프라인 플레이용).
4. 등록된 스테이지는 `PUT /api/admin/stages/{id}`로 갱신한다 (기록은 유지된다).

## 9. 확장 예정

본 스테이지를 설계할 때 추가할 것. 오브젝트 type으로 추가하는 것을 기본으로 한다.

| 요소 | 내용 | 결과 제출과의 관계 |
| --- | --- | --- |
| 추격 봇 | 플레이어를 따라오는 봇. 닿으면 게임 오버 | 실패 시 `cleared: false` |
| 대화 effect | 문 열기, 플래그 설정 등 | |

- ★2 조건은 체크포인트 안정·불안정으로 정했다 ([3.4](#34-별-조건)).
- 숨겨진 요소(★3)와 이상 개체(도감 해금)는 `hidden`, `anomaly`로 구현했다 ([3.6](#36-숨겨진-요소와-이상-개체)). 처치형 버그(여러 번 부딪혀야 하는 등)가 필요하면 `hidden`에 필드를 더한다.
